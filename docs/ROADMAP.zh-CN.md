# 路线图

[English](ROADMAP.md) · [项目首页](../README.md)

下一步优先改善 Windows 上的阅读清晰度、多文档操作和图纸对比速度，以 0.15.1 为基线。当前版本已支持可编辑项目、分屏编辑、查找高亮和图纸复核。[当前版本](RELEASES.zh-CN.md) · [0.15.1 发布验证](VALIDATION.zh-CN.md)

## 下一步优化 · CPU 与 GPU 加速

### 1. 建立性能基线并改善阅读

- 分别测量 PDFium 渲染、PNG 编码、跨进程传输，以及 WebView2 解码与显示的耗时。记录首张清晰页面出现的时间，以及切换标签和缩放后显示清晰画面的第 95 百分位耗时。用多份 PDF、分屏和后台对比同时运行的场景复测。
- 在现有队列基础上优先处理当前视口，其次处理缩略图和后台任务。取消过期请求并丢弃已失效的响应。根据测量决定是否减少 PNG 编码开销，或改用本地二进制传输来省去 Base64 转换。
- 修复页面工具裁剪预览固定使用 1000 像素底图的问题。缩放停止后，按可见区域和显示像素比例请求清晰图像。等待期间保留上一帧，超大页面按需分块，并限制渲染和缓存的内存占用。

### 2. 用 CPU 多核处理独立任务

- 用有上限的 CPU 线程池并行处理独立像素块和图像运算，保留图纸差异的跨块合并与稳定排序。实测少量独立的只读 PDFium 进程能否提高多页渲染吞吐。每个可编辑文档仍按当前版本和顺序写入。
- 批量任务可以取消，运行时仍能响应前台操作。对比基线涵盖旋转页、扫描页、纸张尺寸不一致的页面，以及分块边缘仅有几个像素的变化。

### 3. 评估可选的图纸对比 GPU 加速

- 如果基线显示像素差异计算或配准评分占了主要时间，用 `wgpu` 和 Direct3D 12 试做本地 GPU 加速。总耗时计入显存上传、结果回读、分块合并和报告生成。限制分块大小，显卡不兼容或 GPU 执行失败时回退到 CPU。
- 以 CPU 结果核对差异掩码、区域坐标和 PNG／CSV 输出。GPU 方案须在典型的大幅面 300／600 DPI 图纸上缩短总耗时，并保持上述结果一致。同步记录峰值内存。

**怎么验收。** 在同一台电脑上，用相同文件和设置对照 0.15.1 与优化版。验证 100% 预览静止时停止重绘，高倍缩放能恢复细线细节，后台任务运行时阅读操作仍能响应。记录交互耗时的中位数和第 95 百分位、完整对比耗时及峰值内存。核对取消后源文件完好，项目重开及导出回归通过。

处理和计时均在本机执行。公开资料只使用合成样本或获准公开的样本及其结果。新增依赖优先采用 MIT 或 Apache-2.0，发布前按项目现有规则核查新增 Rust 库、启用的后端和随包依赖的许可证。

## 后续功能规划

### 1. 本地自动保存与异常恢复

- 为每份编辑过的文档保存有限数量的本地恢复草稿。草稿和源 PDF、上次手动保存的 `.jvp` 分开，可按文档关闭恢复或清除草稿。
- 保存页序、可编辑对象及其资源，同时记录阅读位置和缩放。下次启动时显示文档与草稿时间，由用户选择恢复哪些草稿。
- 只有完整快照通过校验后才提交新草稿。写入中断时，回退到最近一份完整草稿。

**怎么验收。** 分屏打开两份 PDF，在一份中旋转或重排页面，在另一份中编辑可换色片段。模拟异常退出，重启后分别恢复草稿，确认片段还能换色和移动，并逐字节核对源 PDF 与手动保存的项目。

### 2. 书签与原生 PDF 批注

- 先做目录树和书签跳转，处理多层书签及目标不可用的情况。
- 页面重排、合并或删除后核对书签目标，导出重开时能跳到正确页面。
- 加入原生文字高亮和备注，导出时保存批注外观。用 Jerrivell PDF 和另一款阅读器重开，核对显示以及能否继续编辑批注属性。

**怎么验收。** 用含多层书签的 PDF 重排和删除页面，导出后在两款阅读器核对目录跳转，并重新编辑批注。

### 3. 离线 OCR

- 先做扫描图像或轮廓文字的选区识别，在本地独立任务中完成。预览识别文字和高亮位置后，再扩展到整页和批量。
- 分别用中英文扫描件、图纸轮廓字和旋转页验收。保留原有文字层，为识别结果提供标识。
- 分别核对引擎与语言数据许可。提供任务进度与取消，在写入可搜索文字层前核对坐标对齐。

**怎么验收。** 用获准使用的各类样本核对识别准确度和高亮位置。在任务进行中取消，验证原文档与源 PDF 仍可正常使用。
